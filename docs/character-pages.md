# キャラ別ページ 設計メモ

2026-10-11 作成。キャラ(メンバー×衣装)ごとに独立したURLのページを作り、キャラ単位でリンクを共有できるようにすること、検索エンジンからキャラ名で流入できるようにすることが目的。

## 決まったこと(ユーザー確認済み)

1. ページには、一覧で詳細を開いたときに見えるものをすべて載せる。
2. ページはスクリプトで自動生成する。
3. X などに貼ったときのカード画像は、サイト共通の `assets/ogp.png` を使う(キャラごとの画像は作らない)。
4. サイトマップを作り、Google Search Console に登録する(Search Console の所有権確認は GA のタグで済んでいる)。

## URL

`c/{メンバーのフォルダ名}/{衣装スラッグ}/`

- 例: `https://ryomochi0918.github.io/nogifra-characters/c/ikeda_teresa/11thbasura5kisei/`
- 1つ目のアクティブスキルの `.mmd` のパス(`data/{メンバー}/{衣装スラッグ}_skill1.mmd`)から作る。英数字だけで短く、2026-10-11時点の345件で重複が無いことを確認済み。
- キャラ名・衣装名をそのままURLに入れると、日本語がエンコードされて長い文字列になるので使わない。
- **公開後は `.mmd` のファイル名(衣装スラッグ)を変えない。**変えるとURLが変わって、共有済みのリンクが切れる。どうしても変える場合は、古いURLに転送用のページを残す。

## ページの構成

上から順に1枚のページに並べる。一覧の詳細画面はタブで切り替えるが、単独のページは上から順に読めるほうが分かりやすく、検索エンジンにも全文が1度に伝わるので、タブにはしない。

1. 一覧へ戻るリンク
2. ティア・属性・期のバッジ、メンバー名(`h1`)、衣装名
3. 「比較」ボタン(押すと、このキャラを選んだ状態で一覧の比較モードを開く)と「リンクをコピー」ボタン
4. アクティブスキルごとに: スキル名(`h2`)、ズーム・拡大表示・凡例のボタン、フローチャート、原文(折りたたみ)
5. パッシブ: 一覧の詳細画面と同じ表
6. フッター(一覧と同じ)・テーマ切り替えボタン

`<head>` には、ページごとのタイトル・説明文・canonical・`og:url` を入れる。タイトルは `{メンバー名}「{衣装名}」のスキル | 乃木フラ スキルフローチャート図鑑`、説明文はスキル1の原文の冒頭から作る。

スキル原文とパッシブはHTMLにそのまま書き出す(JavaScriptで後から入れない)。検索エンジンが確実に読めるようにするため。フローチャートだけは、一覧と同じく `.mmd` を読み込んでブラウザ側で描画する。

## 一覧ページ(`index.html`)の変更

- カードを `<button>` から `<a href="c/…/">` に変える。普通にクリックしたときは今までどおり詳細画面が開く。Ctrl+クリックや中クリックでは、キャラ別ページが新しいタブで開く。検索エンジンも、このリンクをたどってキャラ別ページを見つけられる。
- 詳細画面に「リンクをコピー」ボタンを足す(コピーされるのはキャラ別ページのURL)。
- 詳細画面を開いても、アドレスバーのURLは変えない。URLを変えると、相対パスで読み込んでいるデータ(`data/…`)の基準がずれるなど、影響範囲が広いため。必要になったら別途検討する。
- 今までのURLで開いたときの動きは変わらない。

## 共通化

一覧とキャラ別ページで表示が食い違わないよう、描画処理を `js/common.js` にまとめ、両方から使う。

- テーマ(ダーク/ライト)とMermaidの初期化、`localStorage` の読み書き
- `escapeHtml`、パッシブの表の生成(`passiveTableHtml`・`renderEffectItem`)、`.mmd` の描画(`renderMermaidInto`)
- キャラのURLの組み立て(`characterPath`)、GAへのイベント送信(`track`)

`js/common.js` は、ページの生成スクリプト(Node.js)からも読み込む。パッシブの表やURLの組み立てを、ブラウザと生成スクリプトで二重に書かないため。

## 生成のしかた

- 生成スクリプトは `scripts/build-character-pages.js`(Node.js、外部パッケージ不要)。`data/characters.json` から、全キャラの `c/…/index.html` と `sitemap.xml` を書き出す。
- **生成は GitHub Actions のデプロイ時に行い、生成したファイルはリポジトリにコミットしない。**`.github/workflows/deploy.yml` で、アップロードの前にこのスクリプトを実行する。
  - キャラを追加するたびにスクリプトを実行する必要がなく、実行し忘れることも無い。
  - 345件のページがリポジトリに入らないので、見た目を変えるたびに大量のファイルが差分に出ることもない。
  - 生成に失敗するとデプロイも失敗するので、壊れたページが公開されることは無い(前のページが残る)。
- ローカルで確認するときは、自分で `node scripts/build-character-pages.js` を実行する。生成物(`c/`・`sitemap.xml`)は `.gitignore` で除外する。

## 計測(GA)

- キャラ別ページを開いたときも、一覧で詳細を開いたときと同じ `view_character` イベントを送る(どちらから見られたかは、ページの場所で区別できる)。
- ページビューは、ページごとのURLで自動的に記録される。

## サイトマップ

- `sitemap.xml` にはトップページと全キャラ別ページを載せる。
- Search Console の「サイトマップ」に `https://ryomochi0918.github.io/nogifra-characters/sitemap.xml` を登録する。
- `robots.txt` はドメインの直下(`ryomochi0918.github.io/robots.txt`)にしか置けず、このリポジトリからは置けないので使わない。

## やらないこと(今回の範囲外)

- キャラごとのカード画像の生成
- 詳細画面を開いたときにアドレスバーのURLを変えること
