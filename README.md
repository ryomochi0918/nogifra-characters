# スキルフローチャート図鑑

キャラクターを選ぶと、`skill-flowchart` Skillで作った整合性チェック済みのMermaidフローチャートを
その場でブラウザ描画して見られる、完全に静的なサイトです。サーバーは不要です。

## ローカルで確認する

`fetch()` でJSONと.mmdファイルを読み込む都合上、`index.html` を直接ダブルクリックでは動きません
(ブラウザのCORS制限)。簡易サーバーを立てて確認してください。

```bash
cd site
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

## GitHub Pagesに公開する(無料)

1. GitHubで新しいリポジトリを作成する(例: `nogi-skill-flowchart`)
2. このフォルダの中身(`index.html`, `data/` 一式)をリポジトリの直下にpushする
3. リポジトリの Settings → Pages → Source で「Deploy from a branch」を選び、
   ブランチを `main`、フォルダを `/ (root)` に設定して保存する
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

## 新しいキャラクターを追加する

1. `skill-flowchart` Skillでキャラのスキル画像からMermaidフローチャートを作る
   (`.mermaid` / `.mmd` どちらの拡張子でも中身はテキストなので問題なし)
2. できたファイルを `data/{キャラの半角英数slug}/` フォルダに置く(例: `data/ioki_mao/hodoukyo_skill1.mmd`)。キャラごとにサブフォルダを分けている。
3. `data/characters.json` に1件追記する

```json
{
  "name": "キャラ名",
  "nameReading": "きゃらめいのひらがな(50音順ソート用、必須)",
  "costume": "衣装名やカードの通称",
  "costumeReading": "いしょうめいのひらがな(同キャラ内でのソート用、必須)",
  "title": "スキル名やカードの通称(表示用、tier付きでも可)",
  "tier": "LR",
  "addedDate": "2026-08-01",
  "generation": "5期(スキル画面では確認できないので nogizaka46_members_reading.json 等を参照)",
  "attribute": "努力/感謝/笑顔のいずれか(スキル画面の名前左のマークの色で判別。赤=努力、紫=感謝、黄=笑顔。同じキャラでも衣装が違えば属性が異なることがある)",
  "skills": [
    { "type": "active", "label": "スキル1: ○○", "file": "data/xxx_skill1.mmd", "text": "原文全文(任意)" }
  ],
  "passive": [
    { "condition": "1回覚醒後習得", "effect": ["読点で区切った箇条書き1", "箇条書き2", "..."] }
  ]
}
```

- `nameReading` / `costumeReading` は検索対象ではなく**並び順専用**のひらがなです。読みが分からない場合は空にせず、分かる範囲で埋めるか、Claudeに確認してください(カタカナの通称やフレーズ的な衣装名は読みが一意に決まらないことがあります)。
- `summary`(一覧カードの説明文)と `passive[].name`(パッシブの効果名)は**表示を廃止した**ため、新規追加時は書かなくてよい(データとして残っていても表示には使われない)。
- `passive[].effect` は文字列ではなく**配列**。原文を読点(、)で区切ってそのまま並べる。
- `attribute` を活用すると、「11thバスラ〜◯期生ライブ〜」「真夏の全国ツアー2024・白衣装」のような一部の衣装テンプレートは「同じ期・同じ属性」のキャラ同士でスキル内容が完全一致するため、既存キャラのmmd/textをコピーして名前だけ差し替える高速化ができる(ただし属性が違えば内容も別なので、コピー前に必ず属性が一致するか確認すること)。

## 検索機能

ページ上部の検索ボックスは、キャラ名・衣装名・アクティブスキルの内容・パッシブスキルの内容を横断して検索します。

- **通常モード(既定)**: 部分一致(大文字小文字を区別しない `LIKE '%...%'` 相当)
- **正規表現モード**: 「正規表現」にチェックを入れると、入力値を`RegExp`として評価します。不正な正規表現を入力中は絞り込みを行わず全件表示のままにします(壊れる心配なし)

## 並び順

キャラ名の50音順→同キャラ内は衣装名の50音順、で固定です(`nameReading` / `costumeReading` を使用)。

## 新キャラの追加運用

このゲームは毎週月曜・木曜に新ガチャ(新キャラ)が追加される想定のため、`characters.json`は今後も増え続けます。追加の手順はキャラ追加の項目と同じです(`data/`にmmd等を置いて`characters.json`に1件追記するだけ)。`addedDate`フィールドは今は表示に使っていませんが、将来「新着順」ソートや「NEW」バッジを実装する際のために追加日(`YYYY-MM-DD`)を入れておくと後で楽になります。

## 構成

```
site/
├── index.html                 スポットライト演出のカード一覧+ビューア(1ファイル完結)
├── data/
│   ├── characters.json        キャラ一覧のメタデータ
│   ├── nogizaka46_members_reading.json  現役メンバーの読み仮名・期データ
│   └── {キャラslug}/          キャラごとのMermaidフローチャート(例: ioki_mao/, ikeda_teresa/)
│       └── *.mmd
└── README.md
```

mermaid.jsはcdnjs経由でCDN読み込みしているため、リポジトリ側でのビルドや依存関係管理は不要です。

## 読み仮名の参考データ

`data/nogizaka46_members_reading.json` に、現役メンバー33名分の名前の読み仮名(`nameReading`用)をまとめてあります。出典は非公式データベース[ngzk46seek.jp](https://ngzk46seek.jp/members_list.php)(公式データを元に掲載)。新キャラ追加時はまずここを確認してください。

衣装名(`costumeReading`)は乃木坂46の楽曲タイトルに由来するものが大半です。読み仮名がまとまったサイトとして[n46db.com](https://n46db.com/songs/all-songs-list.php)がありますが、**robots.txtで自動アクセスが禁止されており、Claudeから直接内容を取得できません**。読みが不明な衣装名がある場合は、都度検索するか、このサイトを手動で確認してClaudeに読みを伝えてください。
